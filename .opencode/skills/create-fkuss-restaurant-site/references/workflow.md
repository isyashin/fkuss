# Рабочий процесс Fkuss

## Подготовка каталога

Работай из корня репозитория. Для клиента нужен отдельный каталог:

```text
sites/<slug>/content/
├── restaurant.json
├── menu.json
├── promos.json
├── pages.json
├── settings.json
├── theme.json
├── source-report.json
└── images/
```

Slug состоит из строчных латинских букв, цифр и дефисов и занимает не более
58 символов. Если каталог уже существует, сначала покажи пользователю, какие
файлы будут изменены.

## Яндекс.Еда

Из каталога `template/`:

```bash
npx tsx scripts/ingest-yandex-eda.ts "<url>" --out "../sites/<slug>/content"
```

Мультименю (несколько заведений Еды на одном сайте, см. docs/CASE-MULTI-MENU.md):
запусти инжест по разу на каждое заведение с флагами группы — скрипт сольёт
категории в один menu.json, restaurant.json и логотип возьмутся от первого:

```bash
npx tsx scripts/ingest-yandex-eda.ts "<url #1>" --out "../sites/<slug>/content" \
  --menu-id khinkali --menu-name "Хинкальная"
npx tsx scripts/ingest-yandex-eda.ts "<url #2>" --out "../sites/<slug>/content" \
  --menu-id pirogi --menu-name "Пироги и пицца"
```

После деплоя в админке (Настройки → Синхронизация) добавь источники:
`sync.sources = [{placeSlug: <slug#1>, menuId: khinkali}, {placeSlug: <slug#2>, menuId: pirogi}]`
```

Инжест создаёт черновик. Он не считается готовым, пока не подтверждены телефон,
email, адрес, часы, домен и права на изображения. Сверь количество категорий,
блюд, модификаторов и фото с карточкой ресторана. Зафиксируй недоступные блюда
и группы модификаторов, не сплющивая их в один список.

Пост-инжест проверки и лестница устойчивости (retry → фолбэк размеров фото
под ratio → `--browser`) — в самом скрипте `ingest-yandex-eda.ts`. Дальше
черновик обязан пройти через `assemble-content.ts` с манифестом: DRAFT-поля
(телефон/email/canonical) заменяются данными манифеста, VALIDATE остановит
пайплайн, если манифест неполный. Адрес футера карточки — юридический адрес
продавца, фактический — из опросника (interview.md, батч A).

Мультименю через assemble-content пока не собирается: сайты с несколькими
заведениями Еды делай вручную по docs/CASE-MULTI-MENU.md (инжест с `--menu-id`
напрямую, без assemble).

## Ручной ввод (папка владельца)

Если меню дано файлами, папка приводится к структуре content/ инструментами,
а не руками:

```bash
npx tsx scripts/new-content.ts <dir> --slug <slug> --name "<Название>"   # скелет
npx tsx scripts/normalize-images.ts <фото> <dir>                          # jpg/png → WebP 800/400
```

Дальше папка идёт в `assemble-content.ts` как `source.kind = "folder"` —
он подставит контакты/настройки/тему из манифеста, добьёт дефолты схемы и
провалидирует. Не угадывай цену, вес или состав: отсутствующее оставь пустым
и внеси в `decisions.gaps` манифеста — assemble перенесёт это в
`source-report.json.unresolved`.

## Настройки

- canonical — реальный планируемый домен или согласованный dev-адрес;
- синхронизация с Яндекс.Едой выключена, пока placeSlug не проверен;
- каналы и оплата выключены без соответствующих секретов;
- доставка, бесплатный порог, бронь и лояльность задаются только по решению
  владельца, а не по предположению агента;
- тема и accent должны сохранять читаемый контраст на 360 px.

После подтверждения запускай seed с явными `CONTENT_DIR` и `DATABASE_URL`.
Не направляй seed в базу другого ресторана.
