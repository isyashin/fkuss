# Requesting Code Review

Использовать перед завершением задачи, если изменения нетривиальны
(логика денег, авторизация, вебхуки, деплой, любые изменения > 30 строк).

## Процесс

1. Собери объём изменений: `git status`, `git diff`.
2. Делегируй ревью субагенту `reviewer` (read-only). Дай ему контекст:
   - цель изменения;
   - список файлов;
   - ссылку на релевантные разделы `docs/PLAN.md` / `AGENTS.md`.
3. Получи отчёт: 🔴 блокеры / 🟡 замечания / 🟢 хорошее.
4. Блокеры — исправить до завершения задачи, затем повторное ревью
   по исправленным пунктам.
5. Замечания — исправить или обсудить с пользователем.
6. Покажи пользователю краткий итог ревью.

## Что ревьюер должен проверить (напомни ему в контексте)

- секреты не попали в код/content/git;
- контент не вшит в код (и код не тронут агентом наполнения);
- денежная логика: серверный пересчёт, тесты до кода;
- мобильная вёрстка: 360px, зоны касания ≥ 44px;
- минимальность изменений, соответствие плану.
