# Restaurant Site Builder

Главный навык наполнения шаблона. Агент получает входные данные ресторана
и производит готовый сайт. Код шаблона (`src/`, `scripts/`) не правится
никогда — только `content/`.

## Вход

- Ссылка на страницу ресторана в Яндекс.Еде, ИЛИ
- меню (текст/файл/фото) + фото блюд + логотип.
- Опционально: токены каналов (Telegram/MAX), ключи платёжки.

## Процесс

### 1. Сбор данных

- Яндекс.Еда: используй готовый скрипт инжеста (проверен на боевой ссылке):
  ```bash
  npx tsx scripts/ingest-yandex-eda.ts "<url>" --out <путь-к-content>
  ```
  Он сам вытаскивает категории, блюда, цены, описания, вес, фото (WebP 800px),
  обложку/логотип и пишет дефолты settings/theme. Механика: `/api/v2/catalog/<slug>`
  + `/api/v2/menu/retrieve/<slug>`.
- Если скрипт не сработал (Яндекс изменил API/антибот) — остановись и попроси
  у пользователя меню текстом/файлом. Не обходи защиту.
- Из файлов: прочитать меню, сопоставить фото блюд по названиям;
  несопоставленное перечислить.

### 2. Подготовка изображений

- Скачать фото блюд, сжать (sharp → WebP, разумный размер), назвать
  по id блюда, положить в `content/images/dishes/`.
- Логотип обязателен (`content/images/logo.png`) — нужен для PWA и шапки.
  Если нет — запросить у пользователя.

### 3. Заполнение content/

Строго по `docs/CONTENT-SCHEMA.md`:
- `restaurant.json` — название, slug, адрес, телефон, часы, соцсети, SEO
  (сгенерировать title/description, если их нет).
- `menu.json` — категории и блюда; описания генерируются коротко и
  аппетитно (1–2 фразы), если отсутствуют.
- `promos.json`, `pages.json` — если есть данные.
- `settings.json` — доставка/каналы/лояльность/бронь по дефолтам плана
  (кэшбэк 5%, списание до 20%); значения секретов НЕ вписывать — только
  имена переменных.
- `theme.json` — выбрать пресет по типу заведения:
  - `warm` — трактир, стейкхаус, грузинская/домашняя кухня;
  - `minimal` — кофейня, суши, современное кафе;
  - `elegant` (тёмный) — fine dining, ресторан высокой кухни.
  Accent-цвет — из логотипа. Тон текстов — под пресет.

### 4. Подтверждение

Показать пользователю сводку и ДОЖДАТЬСЯ подтверждения:
- число категорий и блюд, число фото (и сколько блюд без фото);
- выбранный пресет и accent;
- пробелы в данных (нет логотипа, нет часов работы, нет части цен…);
- что будет недоступно без токенов (уведомления в каналы, онлайн-оплата).

### 5. Seed и проверка

- Запустить `npm run seed` (zod-валидация). Ошибки — исправить JSON.
- Поднять сайт локально, проверить главную/меню/заказ.
- Сделать скриншоты мобильных экранов (360px): главная, меню, корзина,
  оформление — показать пользователю.

### 6. Деплой (если запрошен)

- `scripts/deploy.sh <slug> [--domain=...]`, health-check по HTTPS.
- Финальный отчёт: URL, логин админки, список донастройки
  (токены каналов, платёжка, SmartCaptcha).

## Правила

- Никогда не выводить значения секретов.
- Всё, что не удалось извлечь, — явно перечислить в отчёте, не выдумывать
  цены и состав.
- Данные ресторана — только в `content/`, никогда в код.
