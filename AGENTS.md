# AGENTS.md — правила работы с проектом

Проект: **AI-наполняемый шаблон сайта ресторана** (white-label, мультитенантный).
Нейроагент получает меню и фото ресторана (или ссылку на Яндекс.Еду) и собирает
из шаблона готовый сайт на субдомене или собственном домене клиента.

## Главное правило проекта

**Контент отделён от кода.**

- Агент наполнения (`site-builder`) правит ТОЛЬКО `content/` (JSON + картинки).
  Код в `src/` и `admin/` ему запрещён.
- Агент разработки правит код, но не вшивает в него данные конкретного
  ресторана: тексты, цены, телефоны, ключи — всё живёт в `content/` и `secrets/`.

## Карта документации

Читай только то, что относится к задаче:

| Документ | Когда открывать |
|---|---|
| `docs/PLAN.md` | Полный план, этапы, чек-листы приёмки, статус |
| `docs/ARCHITECTURE.md` | Стек, структура, изоляция тенантов, домены, потоки данных |
| `docs/CONTENT-SCHEMA.md` | Формат `content/*.json`, zod-схемы, примеры |
| `docs/DEPLOY.md` | VPS, Docker, Caddy, TLS, домены, бэкапы |
| `docs/CHANNELS.md` | Telegram / MAX / email / WhatsApp: получение токенов и подключение |
| `docs/PAYMENTS.md` | PaymentProvider, ЮKassa и другие эквайринги |
| `docs/BILLING.md` | Платформа владельца: биллинг сайтов, метрики, счета, экспорт |

## Жёсткие правила

1. **Секреты.** Только в `secrets/` (в git не попадают). Никогда не выводить
   значения в ответы и логи — только имена переменных. Не копировать секреты
   в `content/`, в код или в репозиторий сайта-ресторана.
2. **Деньги и заказы — только TDD.** Суммы, бонусы, доставка, скидки,
   биллинг платформы: сначала падающий тест, потом код. Сумма заказа ВСЕГДА
   пересчитывается на сервере — клиентским данным не доверяем.
3. **Минимальные изменения.** Следуй существующим паттернам проекта,
   не рефактори «заодно», не добавляй ничего сверх задачи.
4. **Мобильный приоритет.** Любая вёрстка начинается с 360px.
   Зоны касания ≥ 44px. См. раздел «Mobile requirements» в `docs/PLAN.md`.
5. **План синхронизирован с кодом.** Меняешь этап/статус/решение —
   обнови `docs/PLAN.md` в том же коммите.
6. **Контекст.** Не добавляй файлы в `instructions` конфига OpenCode —
   документы открываются по требованию.

## Команды проекта

Будут заполняться по мере появления (этапы 1–2):

```bash
npm run dev        # локальная разработка
npm run seed       # content/ → БД (zod-валидацией); CONTENT_DIR=<путь> — другой сайт
npm test           # тесты (vitest; DATABASE_URL нужен для интеграционных)
npx playwright test  # E2E (поднимает next start сам)
npm run build      # сборка
```

Инжест и операции (в `template/`):

```bash
npx tsx scripts/ingest-yandex-eda.ts <url> --out <dir>   # Яндекс.Еда → content/
npx tsx scripts/report-metrics.ts                        # метрики → платформа (нужны PLATFORM_URL, SITE_KEY)
```

Платформа (в `platform/`):

```bash
npx tsx scripts/billing-daily.ts   # ежедневное списание + уведомления (cron)
npx tsx scripts/seed-test.ts       # тестовые тариф/сайт/владелец
```

Скрипты сервера (в `scripts/` корня):

```bash
scripts/deploy.sh <subdomain> [--domain=<домен>]   # деплой сайта (реестр портов, БД, compose)
scripts/backup.sh                                   # бэкап всех тенантов (14 последних)
scripts/export-site.sh <slug>                       # экспорт сайта для клиента
scripts/update.sh [--no-restart]                    # git pull → сборка → рестарт всех сервисов
```

## Git-поток

Репозиторий: `https://github.com/isyashin/fkuss` (публичный, ветка main).

- Код правится локально → коммит → пуш. docs/PLAN.md — в том же коммите.
- На сервере исходники живут в `~/resto/src` (clone); обновление —
  `update.sh` (pull → build → restart). tar-синк больше не используется.
- Перед каждым коммитом: секреты только в `secrets/` и env-файлах —
  репозиторий публичный, утечка невосполнима.

## Кастомные агенты и команды OpenCode

- Агент `site-builder` — наполнение сайта из входных данных (только `content/`).
- Агент `reviewer` — read-only ревью изменений.
- Команды: `/new-site`, `/deploy`, `/check-site` — сценарии сборки/деплоя/проверки.

## MCP в проекте

- `context7` — свежая документация библиотек (включён всегда).
- `playwright` — E2E и инжест меню; по умолчанию выключен,
  включается с этапа 3 (`enabled: true` в `opencode.json` + перезапуск OpenCode).
- Postgres MCP не используем: работа с БД через `psql`/`prisma` в bash.

## Ключевые решения (кратко, подробности в docs/PLAN.md)

- Стек: Next.js + Tailwind + Prisma + PostgreSQL, shadcn/ui, Docker + Caddy.
- Каналы заказов: Telegram, MAX, email + кнопка WhatsApp (wa.me).
- Оплата: абстракция PaymentProvider (первая — ЮKassa), fallback «при получении».
- Антибот: honeypot + rate limit по умолчанию; SmartCaptcha — опционально (платная).
- Авторизация гостей: email + одноразовый код. Лояльность: кэшбэк 5%,
  списание до 20% заказа (настраивается в админке).
- Дизайн: 3 пресета на токенах (warm / minimal / elegant), фото — главный контент.
- TLS: per-domain сертификаты Caddy; on-demand TLS с ask-эндпоинтом
  для собственных доменов клиентов.
