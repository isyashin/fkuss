# Кейс: несколько меню на одном сайте (мультименю)

Ресторан ведёт несколько «витрин» на Яндекс.Еде — например, «Хинкальная» и
«Пироги и пицца» — но хочет один сайт с общей корзиной. Платформа умеет такое
с релиза v1.3 (PR №21, №22, №25). Первый живой пример — «Батоно»
(Москва, Автозаводская 18): placeSlug `batono_w98td` + `picceriya__1`.

## Как это выглядит

- **Витрина**: над табами категорий — переключатель групп меню
  («Хинкальная» / «Пироги и пицца»). Корзина общая: гость смешивает блюда
  обеих групп в одном заказе.
- **Заказ**: сервер делает снимок группы меню в каждую позицию
  (`OrderItem.menuName`). В админке у позиции — бейдж группы, под списком —
  сводка «Меню заказа: Хинкальная ×2 · Пироги и пицца ×1».
- **Синхронизация**: `settings.sync.sources = [{placeSlug, menuId}]` —
  каждое заведение Еды синхронизируется в свою группу; «пропавшие» блюда
  гасятся только в категориях своего источника.
- **Совместимость**: сайты без групп меню (`menus: []` в menu.json) работают
  как раньше — переключатель не появляется, пометки пустые.

## Данные

`menu.json`:

```json
{
  "menus": [{ "id": "khinkali", "name": "Хинкальная" }, { "id": "pirogi", "name": "Пироги и пицца" }],
  "categories": [{ "id": "cat-123", "name": "Хинкали", "menuId": "khinkali", "dishes": [ … ] }]
}
```

- `menus` — опционально; `category.menuId` — опционально ("" = вне групп).
- БД: таблица `MenuGroup`, `Category.menuId` (FK, nullable),
  `OrderItem.menuName` (снимок). Миграция `0010_multi_menu`.
- Категории вне групп на витрине получают пункт переключателя «Меню».

## Создание такого сайта (конвейер)

1. **Инжест каждого заведения** — в один каталог, с флагами группы:

   ```bash
   npx tsx scripts/ingest-yandex-eda.ts "<url Еды #1>" --out <content> \
     --menu-id khinkali --menu-name "Хинкальная"
   npx tsx scripts/ingest-yandex-eda.ts "<url Еды #2>" --out <content> \
     --menu-id pirogi --menu-name "Пироги и пицца"
   ```

   Скрипт сливает категории в один menu.json, `restaurant.json` и логотип
   пишутся один раз (от первого заведения; slug второго не валидируется).

2. **Черновики**: заменить `DRAFT_*`-контакты и canonical (readiness-блок
   seed'а их не пропускает); телефон владелец может внести позже через
   админку. Логотип обязателен (нет фото заведения — сделать PNG из любого
   блюда через sharp).

3. **Деплой и seed** как обычно: `deploy.sh <slug>` → миграции →
   `CONTENT_DIR=<content> npm run seed` → bootstrap owner.

4. **Sync**: в админке (Настройки → Синхронизация) добавить оба источника с
   выбором группы меню, включить расписание. Легаси-поле placeSlug читается,
   пока sources пуст.

5. **Проверка**: переключатель на витрине; смешанный заказ; в админке бейджи
   и сводка; `perf-smoke`. E2E-образец — `template/e2e/multi-menu.spec.ts`
   (сид-флаг `SEED_TWO_MENUS=1`).

## Операционные заметки

- Разные цены/наценки на группы: пока общий коэффициент
  (Настройки → Цены) действует на всё меню; per-групповой — по запросу.
- Перенос категории между группами — селект «Меню» у категории в админке
  меню; новая категория создаётся с выбором группы.
- Группы меню создаются на этапе инжеста/seed'а; в админке список групп
  редактируется через контент (удаление/переименование — правка menu.json +
  повторный seed либо SQL).
- Смешанный заказ — один чек; если ресторану нужно разбивать заказы по
  кухням (разные принтеры/станции), это отдельная доработка уведомлений.
