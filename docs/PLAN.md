# PLAN.md — план проекта

**AI-наполняемый шаблон сайта ресторана.** Нейроагент получает меню + фото
(или ссылку на Яндекс.Еду) и собирает готовый сайт на субдомене
`название.нашдомен.ru` или на собственном домене клиента.

Статус этапов: `[ ]` не начат, `[~]` в работе, `[x]` готов.

---

## Зафиксированные решения

### Продукт
- Шаблон content-driven: агент правит только `content/` (JSON + картинки),
  код шаблона не трогает.
- Витрина: меню, карточки блюд, корзина, оформление заказа
  (доставка/самовывоз), галерея, акции, бронирование.
- Админка: CRUD меню/галереи/акций, WYSIWYG текстов (Tiptap),
  настройки доставки/каналов/оплаты/лояльности/брони.
- Админка — НЕ конструктор сайта уровня Tilda, а редактор контента.

### Каналы приёма заказов
- Заказ без онлайн-оплаты → структурированное сообщение (состав, количество,
  суммы, контакты, адрес, комментарий) в: Telegram (Bot API), MAX (Bot API),
  email (SMTP). Каналы включаются/настраиваются в админке.
- WhatsApp — кнопка `wa.me/<номер>?text=<состав заказа>` (клиент сам
  отправляет). Платный Business API — вне MVP.

### Оплата
- Абстракция `PaymentProvider` (createPayment / handleWebhook / getStatus).
- Первая реализация — ЮKassa; ключи — в настройках конкретного ресторана.
- Mock-провайдер для тестов. Fallback всегда: «оплата при получении».

### Антибот
- По умолчанию (бесплатно): honeypot-поле, rate limit по IP и телефону,
  серверный пересчёт суммы заказа по БД.
- Яндекс SmartCaptcha — опционально (платная, тарификация за успешные
  валидации), ключи в настройках ресторана.
- Авторизованные гости заказывают без капчи.

### Авторизация и лояльность
- Вход: email + одноразовый 6-значный код (10 мин, 3 попытки, rate limit
  1/мин на email, 5/час с IP). Сессия httpOnly cookie 30 дней.
- Телефон обязателен в заказе (контакт), но не используется для входа.
- Личный кабинет: история заказов, повтор заказа, адреса, баланс бонусов,
  мои брони.
- Лояльность: кэшбэк бонусами (дефолт 5%), оплата бонусами до 20% заказа
  (дефолт). Оба параметра — в админке. Ledger `BonusTransaction`
  (начисление/списание/сторно), не просто поле баланса.
- Антифрод: бонусы не начисляются на сумму, оплаченную бонусами;
  при отмене заказа начисленные бонусы сторнируются.

### Бронирование
- Слоты (шаг и длительность — в админке), форма: дата/время/гости/имя/телефон/
  комментарий. Статусы: новая → подтверждена / отклонена / отменена гостем.
- Подтверждение кнопкой в админке. Уведомления — в те же каналы, что заказы.
- Схема зала со столиками — фаза 2, не MVP.

### PWA («как приложение»)
- `manifest.json` генерируется из `content/restaurant.json` (название, цвета),
  иконки из логотипа (sharp: 192/512 + apple-touch-icon 180).
- Кнопка «Установить приложение»: Android — системный диалог
  (beforeinstallprompt), iOS — всплывающая инструкция (Safari не даёт
  программной установки).
- Push-уведомления — вне MVP.

### Мультитенантность и домены
- На ресторан: свой контейнер приложения, своя БД + свой пользователь в общем
  PostgreSQL, свой volume для images, свой `.env` в `secrets/sites/`.
- Лимиты CPU/RAM на контейнер в compose.
- Субдомены: Caddy выпускает per-domain сертификаты автоматически
  (HTTP/TLS-ALPN). Wildcard — только если DNS-провайдер даст API (DNS-01).
- Собственный домен клиента: A-запись на IP сервера + on-demand TLS в Caddy
  с обязательным ask-эндпоинтом (allowlist). Переезд субдомен → свой домен
  с 301-редиректом.
- Canonical домен в `settings.json` — используется в письмах, мессенджерах,
  PWA, Open Graph.

### Дизайн (по изучению Noma, Hawksmoor, Sugarfish, Peter Luger, White Rabbit)
- 3 ручных пресета на токенах (`content/theme.json`): `warm` (трактир/
  стейкхаус), `minimal` (кофейня/суши), `elegant` (тёмный, fine dining).
- Токены: accent-цвет, шрифт заголовков (сериф) / текста (гротеск),
  скругления, светлая/тёмная.
- Структура главной: hero (одно большое фото) → о нас → меню/популярное →
  акции → [награды/пресса — опционально] → галерея → контакты с картой.
- Sticky CTA «Заказать» / «Забронировать» на всех экранах.
- Без каруселей, параллаксов, тяжёлых эффектов.
- Тон текстов под пресет (правило в навыке site-builder).

### Mobile requirements (обязательные критерии приёмки)
- Вёрстка от 360px, десктоп — адаптация наверх.
- Зоны касания ≥ 44×44px.
- Sticky нижняя панель корзины с суммой на странице меню.
- Корзина и оформление — bottom sheet, не отдельные страницы.
- Карточка блюда — полноэкранная модалка, фото крупно, «Добавить» снизу.
- Категории меню — горизонтальные прилипающие табы со scroll-spy.
- Кликабельные `tel:` и кнопка маршрута (Яндекс.Карты).
- Правильные клавиатуры (tel/email), маска телефона, минимум полей.
- Фото: AVIF/WebP, responsive, lazy-load. LCP < 2,5 с на 4G.
- SSR для контента, JS только для корзины/форм. Шрифты `font-display: swap`.
- E2E-сценарии прогоняются в мобильной эмуляции.

### Инфраструктура разработки
- Разработка на виртуалке Ubuntu Server (SSH, у пользователя на машине),
  идентичной боевому окружению.
- Секреты: `secrets/` в папке проекта, в git не попадают, на сервере права 600.
- OpenCode: `instructions` только AGENTS.md; MCP — context7 (всегда) и
  playwright (с этапа 3); Postgres MCP не используем (bash + psql/prisma).

### Платформа владельца (SaaS-слой) — сайты продаются
- Проект — коммерческий: сайты ресторанов продаются по подписке.
- **Три кабинета (модель UX, зафиксирована):**
  1. **Админка платформы** (`platform/admin`) — владелец видит все сайты,
     метрики, балансы, управляет ими.
  2. **Админка ресторана** (сайт `/admin`) — настройки сайта, заказы,
     **и подписка/баланс/оплата** (раздел «Подписка», данные тянутся
     с платформы по X-Site-Key: `/api/sites/me`, `/api/billing/topup`).
  3. **ЛК гостя** (сайт `/account`) — история заказов, бонусы, брони.
- Кабинет владельца на платформе (`/cabinet`) остаётся как дублирующий вход.
- **Платформа** — отдельное приложение `platform/` в этом же репозитории,
  свой поддомен (`admin.нашдомен.ru`), своя БД. Код платформы и шаблона
  разделён; платформа не имеет доступа к данным гостей ресторанов.
- **Биллинг**: у каждого сайта баланс (₽) и тариф. Списание ежедневное
  (тариф/30). Пополнение: оплата картой/СБП через ЮKassa платформы
  (переиспользуем PaymentProvider) + генерация PDF-счёта для юрлиц
  (реквизиты — в настройках платформы).
- **Уведомления о балансе**: за 7 / 3 / 1 дней до исчерпания — владельцу
  сайта на email и/или в Telegram (канал задаётся в кабинете платформы).
- **Исчерпание баланса**: льготный период (по умолчанию 3 дня, сайт работает),
  затем приостановка — заглушка «сайт временно недоступен», данные НЕ
  удаляются. Реактивация автоматически после пополнения.
- **Метрики**: каждый сайт шлёт на API платформы (по site key) агрегаты:
  заказы (число, сумма), брони, посещаемость. Посещаемость — свой лёгкий
  счётчик просмотров (без внешней аналитики); Яндекс.Метрика — опционально,
  по желанию клиента.
- **Админка владельца платформы**: список сайтов (состояние, баланс,
  тариф, версия образа, домен), метрики по каждому сайту, история счетов
  и оплат, ручные операции (начислить/скорректировать баланс, приостановить,
  реактивировать).
- **Экспорт сайта**: кнопка → архив (content/ + дамп БД + images) → ссылка
  на скачивание. Доступно владельцу платформы и владельцу сайта.
- Подробности: `docs/BILLING.md`.

## Отчёт по ТЗ (синхронизация и развитие витрины)

**Реализовано по этапам:**
1. Модели: source/externalId/цены-режимы/группы/часы/интервалы/фон/PWA —
   миграция аддитивная, проверена на копии, откат = дамп + схема из git-тега.
2. Синхронизация Яндекс.Еды: изолированный клиент, upsert по externalId,
   атомарный lock, retry, job + админка, 9 интеграционных тестов.
3. Цены: inherit/yandex/manual/coefficient, индивидуальный приоритет,
   округление, зажим в 0, коэффициент на модификаторы, 11 тестов.
4. Модификаторы: группы min/max, radio/checkbox, серверная валидация,
   обязательный тест «3 соуса = 710 ₽».
5. Доставка: окна с tz, minAhead/daysAhead/исключения, порог бесплатности,
   зоны заменяются вариантами (без двойного начисления), снимок в заказе,
   админка вариантов.
6. Главная с полным меню, /menu → /#menu; банкеты с 404 при выключенном.
7. Фон: загрузка (отказ SVG/>8МБ), затемнение, позиция, мобильный флаг.
8. PWA: иконки из логотипа с fallback, версия (cache-bust), офлайн-плашка.

**Тесты:** набор расширен до 135 Vitest шаблона + 35 Vitest платформы и
82 E2E Playwright (360 px Chromium, мобильный WebKit и desktop Chromium,
`workers: 1`). Полный набор пройден на dev-ВМ 2026-09-22 на одноразовых БД;
те же проверки контролирует обязательный GitHub Actions CI.

**Исправлено по ходу:** медленные картинки меню (прегенерированные 400/800px
вместо runtime-оптимизатора), InstallPrompt на /admin, sticky-кнопка на
