## Что подтверждено как сильное

- Изолированные БД/content/env tenant-ов, общий release-образ и разделение кода и контента.
- Серверный пересчёт заказов, миграции, резервные копии, restore-проверки и последовательный rollout.
- `scripts/build-release.py`: чистый `HEAD == origin/main == revision`, immutable `release-<sha>`, OCI revision и резерв свободного места.
- `docs/TOPOLOGY-OPERATIONS.md` и `scripts/topology.py`: актуальный процесс новой топологии.
- Protected `main`, линейная squash-история и обширные unit/integration/E2E/живые проверки.

Архитектуру Next.js/PostgreSQL/Docker/Caddy и современный release builder переписывать не требуется.

## Расхождения и риски

### Документация и эксплуатация

- `AGENTS.md` рекомендовал legacy `scripts/update.sh`, хотя `TOPOLOGY-OPERATIONS.md` запрещает его на новой раскладке. Скрипт использует `latest`, делает `git pull` в исходном checkout и не проверяет чистый `origin/main`/OCI.
- `DEPLOY.md` смешивал актуальные сведения с прежним LAN и старыми образами.
- `ARCHITECTURE.md` содержал прежнюю общую топологию PostgreSQL, несуществующие `deploy.sh --all/--site`, `platform/app` вместо `platform/src/app` и неточное «зоны заменяются вариантами». Фактически геозона ограничивает адрес, а выбранный вариант задаёт тариф.
- Корневой README отсутствовал.

### Локальные файлы и GitHub

- Основной каталог находился на старой `feat/site-pipeline`, отставшей на 64 коммита. Все её шесть коммитов уже влиты squash PR #32 (`21d89c`); это не потерянная работа.
- Локальные QA/редизайн и дополнение журнала не были представлены в `main`. Сырые evidence не должны массово попадать в публичный репозиторий: сначала приватное резервирование и privacy-проверка, в git — только sanitized итоги.
- В двух других worktree обнаружены несохранённые изменения. Они не изменялись; их должна закрыть соответствующая рабочая сессия.
- Локальный `gh` возвращает 401. Факт защиты `main` подтверждён публичным API, детальные required checks/linear history/force-push требуют authenticated-проверки.
- Открытые PR #1/#28/#38/#89 существенно отстают; #38/#89 имеют красные проверки, #1 — draft без checks. Issues #3–#9 требуют сверки с реализованным состоянием, а не механического закрытия.

- QA19-V01 подтверждён в `main`: автоматический `scrollIntoView` в `restaurant-admin.tsx` может скрыть подпись первого дня под мобильной верхней панелью. Исправление — отдельный маленький PR с Playwright-регрессом.
