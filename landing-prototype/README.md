# Лендинг fkuss.ru

Утверждённый логотип и согласованное предложение собраны в адаптивную страницу.
Основной сценарий: понять пользу → посмотреть сайты → оставить контакт.

## Запуск

Из корня проекта:

```powershell
node landing-prototype/server.mjs
```

Нужен Node.js 22.19 или новее. Для первого запуска создайте администратора:
`node landing-prototype/setup-admin.mjs`. Команда запросит логин и пароль
со скрытым вводом; повторно существующие настройки не перезаписывает.
Для текущей рабочей папки администратор уже настроен по данным пользователя.

Предпросмотр: http://127.0.0.1:4185/preview.html.
Сама страница: http://127.0.0.1:4185/.
Админка: http://127.0.0.1:4185/admin.
В предпросмотре можно переключить компьютер / телефон шириной 360 px
и открыть объяснение порядка блоков. Сервер отдаёт только публичные файлы
этой папки; API сохраняет заявки и обслуживает закрытую админку.

## Состав

- `index.html`, `styles.css`, `app.js` — страница и взаимодействия.
- `content/landing.json` — тексты, реальные рестораны, ссылки и источники.
- `assets/` — копия утверждённого логотипа, фавиконка и снимки реальных сайтов.
- `preview.*` — оболочка для обсуждения дизайна, отдельно от лендинга.
- `admin.html`, `login.html`, `admin.css`, `admin.js` — список заявок и вход.
- `server.mjs`, `auth.mjs`, `render.mjs` — HTML из контента, API, сохранение заявок и авторизация.
- `setup-admin.mjs` — первоначальная настройка администратора.
- `tests/server.test.mjs` — проверки API в отдельных временных базах.

Снимки сайтов Бухары, Очаг Grill и Чайханы Алия получены через браузер
29 сентября 2026 года. Ссылки открывают реальные сайты в новой вкладке.

Форма проверяет телефон и необязательную ссылку. Подтверждение появляется
после успешного сохранения заявки сервером. Пока идёт отправка, повторный
клик заблокирован. При ошибке введённые данные остаются в форме.

## Работа с заявками

Админка оформлена в стиле основной админки ресторанов. Заявки расположены
от последней к первой. Для каждой видны дата, имя контакта, телефон, название ресторана
и ссылка на меню, если их указали. Кнопка «Обновить» загружает свежий список.
Поле «Ваше имя» в форме необязательное; обязательным остаётся телефон.
Существующая база получает поле имени автоматически, без удаления заявок.

Раскройте «Статус и комментарий», выберите **Новая / Пообщались / Работаем /
Завершено**, оставьте комментарий и нажмите «Сохранить». Комментарий виден
в списке; изменения остаются после перезагрузки и перезапуска сервера.
Кнопка «Позвонить» открывает набор номера, WhatsApp — чат с телефоном заявки.

Данные и сессии хранятся в `secrets/landing/leads.db`, настройки входа —
в `secrets/landing/admin.json`. Пароль хранится как scrypt-хеш. Эта папка
исключена из Git и недоступна через HTTP. Сервер проверяет права на чтение
и изменение заявок; сессия действует 8 часов. Базу следует включить
в резервное копирование при размещении на сервере.

Для HTTPS за прокси задайте `FKUSS_LANDING_ORIGIN=https://<домен>`:
это адрес для проверки происхождения запросов и включения Secure-cookie.
Локальный сервер слушает `127.0.0.1:4185`. Продакшн запускается отдельным
контейнером со своей сетью, SQLite-базой и бэкапом; см. [публикацию](ops/README.md).
В продакшне страница отдаётся полностью заполненной до загрузки JavaScript,
публичные файлы кешируются, предпросмотр отключён. Лимиты запросов принимают
адрес посетителя только от явно настроенного прокси.

## Как применены идеи Канемана

| Принцип | Решение на странице |
|---|---|
| Быстрое первое впечатление | Результат, срок, один основной призыв и реальный сайт в первом экране |
| Точка отсчёта | Два сценария: уже есть агрегатор или пока нет онлайн-заказов |
| Неприятие потерь | Экономию на комиссии повторного заказа объясняем как сохранение части выручки |
| Обдуманная проверка | Реальные сайты, полный состав услуги, цифры со ссылками и условия запуска |
| Понятное следующее действие | В заявке обязателен только телефон; меню можно прислать позже |

Это наше применение идей к задаче продажи сайтов.
Источники не устанавливают готовую формулу лендинга или гарантированный
рост конверсии. Результат проверяется после запуска.

Основа: [Daniel Kahneman, Maps of Bounded Rationality, 2003](https://kahneman.scholar.princeton.edu/sites/g/files/toruqf3831/files/kahneman/files/maps_bounded_rationality_dk_2003.pdf).

Исследования отрасли показаны с точным смыслом цифр, названием источника
и годом. Отзывы клиентов добавляются после получения реальных отзывов.
Выбора тарифа нет; стоимость согласуем перед запуском.

## Проверка

29 сентября 2026 года проверено в браузере:

- Страница на экране 1280 px и мобильный предпросмотр 360 px.
- Основная кнопка приводит прямо к форме; телефон получает фокус.
- Пустой телефон и неверная ссылка показывают понятные ошибки.
- Для заполнения заявки достаточно телефона; остальные поля необязательны.
- Отправленная заявка появляется в админке; две заявки показаны от новой к старой.
- Вход с неверным паролем, успешный вход и выход проверены в браузере.
- Статус и комментарий сохраняются после перезагрузки; контакты ведут на
  корректный `tel:` и `wa.me`. Админка и вход проверены на ширине 360 px.
- Ссылки источников, полные названия исследователей и годы видны рядом с цифрами.
- Все изображения загружаются; логотип совпадает с утверждённым файлом.
- В обеих страницах подключена фавиконка — оранжевая F-вилка из логотипа.
- Превью сайтов сохраняют исходные пропорции при изменении ширины;
  фиксированная высота и обрезание по бокам убраны. Проверено
  на компьютере и в мобильном предпросмотре 360 px.
- На компьютере нет горизонтального переполнения; интерактивные элементы
  соответствуют минимальной зоне касания 44 px.

26 тестов API и рендеринга проходят: `node --test landing-prototype/tests/*.test.mjs`.
3 проверки бэкапа/восстановления: `python3 landing-prototype/tests/backup_test.py`.
Проверены защита данных, серверная валидация, параллельные заявки,
сохранение после перезапуска, статусы, комментарии, имя контакта и миграция базы.
Тестовые записи
браузерной проверки удаляются; реальные заявки не затрагиваются.

Синтаксис JavaScript и JSON проверен. Исходный прототип админки
`test-front/app` сохранён.

Лендинг опубликован на https://fkuss.ru в отдельном контейнере от
сайтов ресторанов. Исходная конфигурация Caddy сохранена для отката;
источник релиза, частные файлы и бэкапы лежат в своих каталогах на VPS.

## Согласованный дизайн лендинга

Согласованный дизайн опубликован на https://fkuss.ru/ (релиз ea43ba0).
Предпросмотр на https://design.fkuss.ru/ работает отдельно и не переключает
главный сайт. Порядок изоляции — [ops/PREVIEW.md](ops/PREVIEW.md).
Разбор исходной страницы и решений — [дизайн-ревью](../docs/LANDING-DESIGN-REVIEW.md).

На первом экране показаны действующий сайт и иллюстрация мобильного меню.
Возможности объясняются через путь гостя и работу команды; иллюстрации
интерфейсов обозначены как примеры. В форме ресторан и ссылка на меню
находятся в необязательном раскрывающемся разделе.

В карточке команды показан снимок работающего прототипа test-front: список
заказов с доставкой и самовывозом, статусы и состав выбранного заказа.
Снимок сделан в отдельной локальной копии: имена заменены, адреса скрыты,
телефоны заменены фиктивным номером и размыты до захвата экрана. Исходный
test-front не изменён. WebP размером 1000×868 весит 89 КБ, загружается
отложенно и открывается крупнее по нажатию.

Manrope загружается локально, файлы WOFF2 и лицензия SIL OFL находятся
в assets/. Утверждённый логотип уменьшен до размера, достаточного для
экранного показа, без изменения формы. Оригинальный PNG сохранён.
В режиме FKUSS_LANDING_PREVIEW=1 заявки помечены как тестовые, страницы
исключены из индексации; для них используется отдельная база.
