# Панель администратора «Очаг Grill»

Кликабельный образец интерфейса будущей админки. Внешний вид, компоновка, названия разделов и основные сценарии этого проекта служат заданием для переноса в рабочую админку. Проект находится отдельно от `template/admin` и не меняет действующий сайт.

## Запуск

В каталоге `test-front` установите зависимости и запустите предпросмотр:

```bash
npm install
npm run dev -- -p 3097
```

Откройте `http://localhost:3097/`. Для проверки:

```bash
npm test
npm run build
```

Служебный индикатор Next.js отключён через `next.config.mjs`.

## Состав и поведение

- Основная навигация: «Заказы», «Брони», «Меню», «Настройки».
- В заказах работают фильтры и сортировка, переключение вкладок, изменение количества блюд, добавление и удаление блюд. Статус можно выбрать в любом направлении, в том числе вернуть с «Готов» на «Готовится» или «Новый». Сумма блюд пересчитывается при редактировании.
- В бронях можно открыть запись и подтвердить её. В меню 10 категорий и 75 блюд: поиск, редактирование названия, цены, веса, описания, состава и фото, стоп-лист, добавление блюда в выбранную категорию. Окно «Добавить блюдо» в заказе использует этот же полный каталог и позволяет только выбрать готовую позицию.
- «Настройки» показывают блоки последовательно в одну колонку: оформление панели, звук, администратор, ресторан, оформление сайта, доставка, цены/оплата/лояльность, связь с гостями, каналы уведомлений, параметры бронирования, акции, галерея, банкеты, страницы, синхронизация, печатные материалы, подписка.
- Анимированный переключатель светлой и тёмной темы доступен на каждой странице и меняет только тему админки. Параметры оформления публичного сайта находятся отдельно в настройках.
- Звук настраивается только в настройках: два стандартных варианта, загрузка своего файла, прослушивание и удаление. При удалении своего файла выбирается первый стандартный звук.
- В заказе показан только выбранный гостем канал связи: компактная иконка в строке и ссылка в деталях. Если администратор скрыл этот канал, остаётся номер телефона — другой мессенджер не подставляется. Для броней выбор гостя пока не задан, поэтому там видны оба разрешённых канала: WhatsApp и Telegram. Видимость каналов меняется в блоке «Связь с гостями» и сразу сохраняется в `localStorage` браузера под ключом `ochag-admin-guest-channels`.
- Вымышленные гости используют один пример номера `+7 (903) 555-23-92`. Ссылки WhatsApp и Telegram собираются из нормализованного номера. Telegram может найти гостя по номеру, только если это разрешено его настройками приватности: [Telegram FAQ](https://telegram.org/faq).
- Логотип ресторана используется в панели и как favicon.
- В настройках можно менять поля и переключатели, добавлять зоны доставки, особые дни, акции, фото и залы, просматривать страницы и макет печатных материалов. Кнопки «Сохранить» сохраняют поля настроек в браузере.

## Границы текущей реализации

Это интерфейсный образец, а не рабочая админка. Логотип, фото и блюда взяты из контента «Очаг гриль»; заказы и брони вымышленные. Локальный снимок меню сверен с [действующей витриной](https://ochag-grill.fkuss.ru/menu) 25 сентября 2026 года: 75 блюд в 10 категориях, цены как на витрине в день сверки. У 74 блюд есть локальные фото; у том яма с креветками фото отсутствует и на витрине. Эти данные могут устареть при изменении рабочего сайта. Исходные данные хранятся в локальных файлах `lib/` и `public/dishes/`. Изменения заказов, включая статусы, броней и меню живут только в памяти страницы и сбрасываются при обновлении. Выбор видимых мессенджеров и кнопки «Сохранить» в настройках записывают данные в `localStorage` текущего браузера; они не сохраняют данные в рабочую базу. Загруженные изображения и аудиофайлы доступны до обновления страницы.

Предпочтительный канал в заказах задан вручную для визуальной проверки. В прототипе нет оформления заказа, где гость мог бы выбрать его сам. Русские названия стадий доставки основаны на [модели Яндекс Еды](https://yandex.ru/dev/eda-vendor/doc/ru/ref/); «Выдан» — отдельный финал самовывоза в этом проекте. Обратный выбор статуса работает только в прототипе и не повторяет ограничения API Яндекс Еды.

Рабочая админка в `template` пока не получила интерфейс и функции этого образца. Настройки синхронизации с Яндекс.Едой показаны в прежнем блоке «Настройки», но живой синхронизации нет: кнопка запуска сообщает, что она недоступна. В редактировании блюда сохранён выбор режима цены; режимы цены Яндекс.Еды выключены, поскольку текущая цена из её API недоступна локально. Ручная цена меняет только демо-каталог. Экспорт печатных материалов, биллинг и пополнение баланса требуют рабочих сервисов: соответствующие кнопки сейчас показывают сообщение об ошибке, а не выполняют операцию. В списке способов оплаты значение `mock` обозначает внутренний вариант «Другой провайдер» и не проводит оплату. Для заказов итоговую сумму нужно рассчитывать на сервере с учётом доставки, скидок и бонусов; отображаемая здесь сумма — сумма блюд.

При реализации нельзя переносить локальные данные и `localStorage` как постоянное хранилище. Сохранение, файлы, уведомления, права доступа и интеграции должны работать через существующие серверные механизмы проекта. Телефоны и прочий контент должны оставаться в данных ресторана, а не в коде компонентов.

MAX отложен и не показывается в прототипе. Если к нему вернутся при разработке рабочего продукта, для автоматических уведомлений понадобится бизнес-профиль и бот ресторана: гость запускает бота по ссылке с одноразовым токеном заказа, сервер получает `chat_id` и отправляет сообщения через API. См. [документацию MAX](https://dev.max.ru/docs/chatbots/bots-coding/prepare).
