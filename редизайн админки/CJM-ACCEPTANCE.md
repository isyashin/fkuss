# Сценарии приёмки всего редизайна

**Статус:** это обязательная матрица для будущего рабочего приложения, а не отчёт о пройденном E2E. Локальные HTML-макеты не подключены к серверу; их браузерный прогон в текущей среде заблокирован политикой доступа к `file://`. Исполнитель отмечает пункт выполненным только после запуска проверки и фиксации результата.

## Как проверять

- Проверять на **двух tenant-ах** с различными меню, настройками, зонами и изображениями. Гость и администратор одного ресторана не должны видеть данные другого.
- Использовать владельца, сотрудника без PIN, сотрудника с действующим PIN и неавторизованного пользователя. Проверять и экран, и прямой URL, и server action/API.
- Для каждого экрана смотреть 360, 390, 768, 900 и 1280 px; отдельно 320 px на переполнение. На телефоне проверить клавиатуру, нижнюю навигацию, сохранение и возврат к списку. Кликабельные зоны — от 44 px.
- Проверять успешный ответ, ошибку сервера, задержку, повторную отправку и конкурентную правку. После успеха обновлять страницу и сверять БД/витрину; локальное сообщение макета доказательством сохранения не служит.
- Деньги, бонусы и доставку сначала покрыть падающими unit/integration-тестами; итог заказа всегда сверять с результатом сервера.

## A. Сквозные маршруты

| ID | Шаги | Критерий |
|---|---|---|
| A01 | Владелец входит и проходит «Заказы → Брони → Меню → Настройки», затем все шесть групп настроек. | Четыре верхних пункта, активное состояние и рабочие прямые адреса; группы не появляются как пятый верхний раздел. |
| A02 | Сотрудник без PIN открывает три рабочих раздела, редактирует блюдо и пытается открыть настройки по ссылке и прямому URL. | Меню редактируется; вместо данных владельца открывается PIN-gate. |
| A03 | Сотрудник вводит верный PIN, открывает настройки и загружает владельческое изображение; затем срок разблокировки заканчивается. | `manage` действует только во время разблокировки; после истечения доступ вновь закрыт и API отказывает. |
| A04 | Неавторизованный пользователь открывает прямой URL внутренней настройки, действия и загрузки. | Вход или отказ без раскрытия данных/файлов. |
| A05 | Изменить поле, перейти в другой раздел, к другому блюду, по старой ссылке и закрыть вкладку; повторить после успешного сохранения. | При несохранённом вводе есть выбор остаться или потерять правки; после сохранения предупреждения нет. |
| A06 | Обновить страницу после сохранения; вызвать ошибку сервера и конфликт двух вкладок. | Успех сохраняется в БД; ошибка оставляет форму и выбор; конфликт не перезаписывает чужую правку молча. |
| A07 | Перейти по старым URL `/admin/delivery`, `/admin/team`, `/admin/restaurant`, `/admin/promos` с каждой ролью. | Совместимый защищённый экран или защищённый редирект; обход PIN невозможен. |
| A08 | Проверить профиль, выход, личную тему, открытие сайта, колокольчик, звук во вкладке и счётчики заказов/броней. | Функции сохранились; тема панели не меняет витрину; просмотр колокольчика не обнуляет необработанные записи. |
| A09 | Сменить tenant и выполнить поиск, загрузку изображения, сохранение настроек и заказ. | Во всех чтениях/записях tenant-изоляция; пути файлов относятся к правильному `CONTENT_DIR`. |

## B. Рабочее место сотрудника

| ID | Шаги | Критерий |
|---|---|---|
| B01 | Заказы: «Текущие», «Новые», «История»; доставка/самовывоз; поиск по №, имени и телефону; пустой результат; несколько страниц. | Фильтрация охватывает все записи tenant-а, а не только первую страницу; выбор и счётчики согласованы. |
| B02 | Провести доставку по цепочке `new → accepted → cooking → ready → handed_to_courier → delivered`. | На каждом шаге есть только допустимый следующий переход, после финала нет действий. |
| B03 | Провести самовывоз по цепочке `new → accepted → cooking → ready → issued`; отменить другой незавершённый заказ. | Тип определяет финальный шаг; отмена подтверждается и переносит запись в историю. |
| B04 | Открыть заказ с онлайн-оплатой/платежом и завершённый заказ; затем редактируемый заказ при получении. | Редактор состава доступен только согласно `orderEditBlockReason`; сервер повторяет запрет. |
| B05 | Изменить количество, добавить блюдо с модификаторами, удалить позицию, попытаться сохранить пустой состав, отменить правки и сохранить корректный состав. | Группы и модификаторы не теряются; `expectedUpdatedAt` защищает от конфликта; сервер пересчитывает товары, доставку, бонусы и итог. |
| B06 | Брони: «Предстоящие», «Ожидают», «История»; поиск, пустой результат, выбор по прямой ссылке `?selected=` и обновление. | Хронология учитывает часовой пояс ресторана; выбранная запись сохраняется, пока входит в фильтр. |
| B07 | Подтвердить/отклонить новую бронь, отменить подтверждённую; открыть отклонённую и старую. | Действия соответствуют серверным разрешённым переходам; после действия список, деталь и бейдж обновлены. |
| B08 | Меню: выбрать категорию, поиск, «В меню»/«Недоступны», пустой результат и блюдо. | Список и редактор синхронны; на телефоне деталь открывается вместо списка, на широком экране рядом. |
| B09 | Создать и изменить блюдо; проверить `inherit`, `yandex`, `manual`, `coefficient`, ручную цену и отсутствие цены источника. | На сайте и в заказе используется цена действующего `recomputePrices`; недоступные режимы не предлагаются. |
| B10 | Переключить ручной стоп при доступном и недоступном источнике; проверить все четыре сочетания флагов. | `available` вычисляется сервером; снятие ручного стопа не обещает вернуть отсутствующее в источнике блюдо. |
| B11 | Загрузить фото, вызвать ошибку загрузки, повторить, удалить блюдо с подтверждением, создать категорию и дубликат. | Файл не считается сохранённым до ответа; старая фотография не теряется при ошибке; удаление учитывает связанные записи. |

## C. Семнадцать экранов настроек

| ID | Экран и маршрут владельца | Что проверить |
|---|---|---|
| C01 | Данные и контакты | Имя, телефон, email, адрес, публичные ссылки и логотип; загрузка и ошибка файла; сохранение не стирает `slug`, `cuisine`, SEO и другие скрытые поля. |
| C02 | Часы работы | Семь дней, выходной, время через полночь, особая дата, часовой пояс; производный `workHours`; атомарная запись связанных ключей. |
| C03 | Оформление | Три пресета, цвет, фон, положение, затемнение и скрытие на телефоне; остальные токены темы не исчезают; личная тема панели независима. |
| C04 | Страницы | Выбор любой реальной `Page`, правка заголовка и текста, предпросмотр/переход на опубликованную страницу; `slug` и другие страницы не меняются. |
| C05 | Фотографии | Несколько файлов, alt-подпись, удаление, невалидный/слишком большой файл и ошибка загрузки. |
| C06 | Акции | Создание, правка, удаление, изображение, даты и отдельный `enabled`; истёкшая акция скрыта даже при включённом переключателе. Старые акции после миграции включены. |
| C07 | Банкеты | Общие параметры, несколько залов и фото каждого, правка/удаление; сохранение другого раздела не стирает `banquets`. |
| C08 | Печатные материалы | Визитка и магнит, цвет/логотип/телефон/адрес, QR на canonical текущего ресторана, экспорт PDF/PNG/SVG и проверка экспортированных файлов. |
| C09 | Доставка и самовывоз | Общие флаги, минимум, карта и геометрия зон, тарифы, вариант, дни/интервалы/исключения, ошибка геокодера. Первый выпуск сохраняет прежние `price/freeFrom` варианта. |
| C10 | Оплата и бонусы | Действующие методы оплаты, в том числе уже настроенный `mock`, кэшбэк и лимит списания; секреты не попадают в браузер; соседние настройки не сбрасываются. |
| C11 | Бронирование | Включение, шаг слота, вместимость, время до визита, отключённые поля и согласование с расписанием/часовым поясом. |
| C12 | Правила цен | Общий режим и процент, ручные исключения блюд, модификаторы; изменение правила и `recomputePrices` атомарны, ошибка откатывает всё. |
| C13 | Импорт из Яндекс.Еды | Идентификатор, расписание, запуск сейчас, последнее состояние и ошибка; сохранение соседней настройки не стирает `sync`. |
| C14 | Связь с гостем | Публичный WhatsApp, отдельный номер заказов, кнопка после оформления и ручные ссылки ответа; три назначения не смешиваются, пустая ссылка не показывается. |
| C15 | Уведомления | Telegram/MAX/email, адреса/ID, звук панели, `none`, загрузка своего файла, повторы 1–20; счётчики работают и без звука. |
| C16 | Сотрудники | Создание, изменение имени/роли, пароль, выключение, отзыв сессий; нельзя отключить последнего активного владельца. |
| C17 | Подписка | Тариф, баланс, счета, метрики, пополнение, ошибка/отсутствие платформы; демонстрационная фраза не заменяет реальные данные. |

## D. Денежные и технические регрессии

- Сумма корзины, `api/order`, редактирование заказа и отображение в админке совпадают для текущего режима доставки. Старые заказы и цены вариантов не меняются после визуального переноса.
- Если отдельно включена модель `zone-v2`, проверить пороги и надбавку, адрес вне зон, выключенную/недоступную зону, отказ геокодера, закрытый день, заказ ниже минимума, самовывоз, бонусы и бесплатный порог. Старые tenant-ы остаются в `legacy-option` до проверенной миграции.
- Сохранение контактов не меняет часы; зон — оплату и банкеты; темы — скрытые токены; уведомлений — `sync`. Две параллельные правки разных разделов не конфликтуют, одной секции — обнаруживают конфликт.
- `npm test`, `npm run build` и `npx playwright test` проходят в `template/`; для интеграционных тестов подготовлен `DATABASE_URL`. Проверка верстки включает клавиатуру, увеличение текста, длинные данные и отсутствие горизонтальной прокрутки.

Финальный отчёт исполнителя должен перечислить реально запущенные команды, пройденные ID и оставшиеся ограничения. Не заменять прогон E2E ручным чтением кода или просмотром HTML.
